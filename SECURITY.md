# Security policy

## Reporting a vulnerability

Report security problems privately through [GitHub private vulnerability reporting for this repository](https://github.com/liorinbar10/lior/security/advisories/new). Do not put details of a security problem in a public issue or pull request.

Include the affected file or project, steps to reproduce and the impact as you understand it.

If private vulnerability reporting is not enabled for this repository, open an issue that says only that a security concern exists and asks for private vulnerability reporting to be enabled. Do not include any details there.

## Scope and response

This is a personal repository maintained by one person. Reports are handled on a best-effort basis; there is no guaranteed response time and no bug bounty.

There is no supported-version matrix. Fixes are applied on the default branch, and the outcome of a report is recorded in the advisory thread. Reporters who want credit are named in the advisory when a fix is published.
